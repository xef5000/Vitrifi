01 / The workflow

A little intent. A lot less guesswork.

01YOU AUTHOR

Declare what matters.

Name a feature, map a resource, and add policies to ordinary Java. Keep business logic in its own language.

@Forbid(action = "write", resource = "Carts")
02THE COMPILER DERIVES

Generate the relationships.

Compiler analysis follows supported calls and Spring wiring. Signatures, dependencies, and SQL effects become a local .vitrifi file.

vitrifi generate --root your-app
03EXECUTION ADDS EVIDENCE

Check what really happens.

Static checks enforce supported effect policies. Instrumented tests check actual JDBC attempts on the paths they exercise.

vitrifi verify --java --root your-app -- mvn test

04 / Know what you know
Evidence with its
boundaries attached.
A trustworthy view tells you where its knowledge ends. Vitrifi keeps authored intent, derived facts, and observed behavior distinct.
↳
Derived from source
Java signatures, supported calls, bounded Spring wiring, and recognized SQL effects. Unknown reachable behavior produces incomplete.
STATIC ANALYSIS
✓
Observed in execution
Fresh scenario evidence from synchronous Spring proxies and instrumented JDBC. An error-path policy needs an actual exceptional invocation.
RUNTIME EVIDENCE
…
Still outside the view
All possible inputs, arbitrary libraries, async work, database triggers, and durable transaction outcomes. Passing scenarios cover the paths they exercised.
EXPLICIT LIMITS
Start with Java + Spring. This generated workflow supports Java 21+ and a conservative SQL subset. Python, Ruby, JavaScript, and TypeScript currently have the earlier authored workflow.
