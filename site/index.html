A little intent. A lot less guesswork.

02 / Start with the flow

Read what executes.
Follow what it calls.

A workflow is executable source. Start at an operation, follow each call to its typed action, then open the bound Java method to inspect the calculation.

Checkout.Discounts.workflow.vitrifiAUTHORED EXCERPTS
operation preview(cartId: "java.lang.String") -> "dev.vitrifi.example.checkout.Cart" {
  effects [read Carts];
  let cart = call load(cartId);
  return cart;
}

action load(cartId: "java.lang.String") -> "dev.vitrifi.example.checkout.Cart" {
  bind java "dev.vitrifi.example.checkout.CheckoutActions.load(java.lang.String)";
  effects [read Carts];
}

FOLLOW A CALL

preview → load → Java

operation defines the public flow. let binds a result once; call invokes a declared action. return ends the operation.

action defines the native method’s typed contract. bind java points at its implementation. effects bounds recognized resource effects; it does not declare a Java method pure.

resource Carts table "carts"; gives SQL effects a feature-level name. The workflow compiler checks every branch against its declared policies.

WHAT THE LAWS ALLOW
A small, explicit algebra.
  • Move a following continuation into each branch that can continue.
  • Select a literal true or false branch.
  • Replace identical branches with their shared body.
  • Compare terms allowing consistent local variable renaming.
Every intermediate must still pass type, scope, exit and rejection-effect checks. There is no rule for reordering, duplicating or removing arbitrary Java calls.

          
WHAT THE CERTIFICATE PINS
Source and assumptions travel together.
Exact workflow endpoints, an immutable Git baseline, native source and resources, target selection, ordered dependency contents, analyzer, Java runtime properties and checker implementation.
Both endpoints use the same pinned current dependency environment. Checking reconstructs the inputs and replays the derivation; it never trusts a recorded success flag or reruns proof search.
Read the proof guide ↗

        

        
The claim is restricted workflow equivalence under unchanged native behavior. It preserves values, business rejection and action-failure behavior, divergence, and ordered action invocations. It abstracts from timing, source locations and resource exhaustion. The Rust kernel and JVM are trusted implementations, not formally verified artifacts. Business correctness and fresh runtime tests remain separate obligations.
